# 使用体验审查

日期：2026-10-22。对象：公开版 VASPsolKit 0.4.0 工作树，修订尚未发布为新 tag。

## 方法与边界

独立体验智能体按新用户方式操作真实命令行入口，主线程复现、修复并运行回归测试。
试用使用临时 Case、合成结构和仅供解析的赝势元数据；不运行 VASP，不提交或取消集群任务。
子进程使用隔离的 HOME、状态目录及 PATH，避免读取真实提交回执或调用服务器调度器。

## 已修复问题

| 问题 | 原表现 | 当前行为 |
| --- | --- | --- |
| 缺文件没有可执行下一步 | 菜单推荐补齐文件，但操作不可执行 | 推荐 inputs，新增菜单 14；显示预览后只补缺失文件 |
| KSPACING-only 被错误阻挡 | VASP 支持，但程序要求 KPOINTS | 共享采样策略贯通准备、指纹和提交前检查 |
| 工具菜单需要再次手动操作 | 初始化中转到另一个交互菜单 | 显式参数驱动 VASPKIT 1.5.x 的 103/102；支持原生后端 |
| 每个体系重复配赝势 | 没有独立输入设置 | 显式保存本机库和映射，新增元素仍需确认，不保存显式网格 |
| 菜单补全无法选择保存 | 命令行有保存参数，但 14/02 没有询问入口 | 补全赝势时询问是否保存，默认不保存；取消补全不保存设置 |
| 补全失败后的恢复提示 | 只提示查看状态，没有指出可重试的入口 | 提示修正路径或参数后重新选择 14/02，并保留 03 诊断入口 |
| README 混合用户与开发内容 | 入门流程被构建、内部机制和修复历史打断 | 首页按安装、输入、菜单、续跑和结果组织；分设使用手册与安装指南，开发内容移入 CONTRIBUTING |
| 自动分配无法切换服务器分区 | 只改 tasks，继续使用原分区（常为 compute） | 先查询并选择有效分区，再自动分配；单节点每节点 tasks 同步总任务数；查询失败不改原配置 |
| 推荐步骤停在结果收集 | 全部收敛后始终推荐 collect | 当前 summary 存在后推荐拟合，哈希匹配后显示结果位置 |
| 拟合可能覆盖详细审计 | 菜单输出到 results 根目录 | 菜单拟合输出固定到 results/eu，详细审计保持独立 |
| 批处理初始化缺参 | `init --yes` 仍等待 SHE reference 等输入，管道保持打开时会卡住 | 一次列出缺少的参数并退出，写入前检查 |
| 无 TTY 且省略 --yes 的缺参调用 | init 缺基础必填项或 configure-reference 缺参考值时等待开放的 stdin | 同样立即列出缺项，提示完整参数加 --yes 或交互终端，不写 Case |
| 批处理修复缺任务编号 | `repair --yes` 缺少 `--job` 时仍会等待输入 | 要求显式指定任务，检查前即报错 |
| 菜单操作中途 EOF/Ctrl-C | 选择初始化后退出会显示 Python traceback | 正常退出，并提示提交中断时先核查状态和回执 |
| 非法选择编号 | `0`、负数被 Python 负索引解释为有效选项 | 只接受当前菜单的 `1..N` |
| 拒绝中性任务提交 | 回答 `n` 仍进入控制器并抛出 PermissionError | 明确取消，不创建提交动作 |
| 重复初始化 | 部分 init 路径能覆盖现有状态，清除任务记录 | 发现配置或状态文件立即拒绝，提示继续原 Case |
| 并发初始化的旧确认 | 等待确认期间，另一个会话已初始化并提交；旧会话随后清空 Job ID | 写入前持状态锁重新检查目标；已建立的状态不可覆盖，模板变化使旧预览失效 |
| INCAR 同行参数丢失 | 修改首个标签会删掉分号后的其他标签 | 按赋值范围修改，保留相邻参数、注释和未知标签 |
| INCAR 读取不一致 | 小写、分号和注释中的标签导致漏读或误读 | 预览、准备及 NELECT 核查共用解析器 |
| 等价数值误报冲突 | `EB_K=80.0` 与 `80` 被判不同 | 按数值比较，同时保留用户原始写法 |
| 常见 CLI 错误难理解 | 缺配置等错误直接显示堆栈 | 简短原因和恢复提示，`--debug` 保留原始堆栈 |

INCAR 的重复活动标签会在初始化审查中报告；有意修改某标签时更新其全部活动赋值，
避免残留旧值覆盖修改。双引号内部内容不会被误判为顶层标签。大括号嵌套语法暂不支持，
会明确报错，不会静默修改错误作用域。

## 可复现验证

```bash
python -m pytest -q tests/test_cli_user_experience.py tests/test_cli_error_messages.py tests/test_incar_template_safety.py
python -m pytest -q tests/test_cli_initialization_race.py
python -m pytest -q tests/test_new_user_menu.py tests/test_user_cli_portability.py tests/test_documentation_examples.py
python -m pytest -q
```

黑盒测试覆盖实际 `python -m vaspsolkit` 入口，包含 stdin 保持打开的超时回归，
不能仅用关闭 stdin 的测试替代。测试的提交回执写到独立临时目录，不使用操作者的状态目录。
已有提交回执屏障、未知状态不重提、五点拟合和科学来源测试继续保留。
第二轮复验发现并修补了并发初始化问题；回归测试验证旧确认不会清除后来会话保存的 Job ID。

## 尚未覆盖

- 真正的跨服务器 VASP/VASPsol 计算验收，仍需各服务器的小体系测试。
- VASPKIT 1.5.x 之外的自动接口；当前版本不猜测其他版本任务号。
- 单一模板驱动的完全无人值守全流程；当前 `run` 仍只执行一次中性提交或状态提示，不代表后台调度服务。
- `next` 同样只推进一步；不在退出终端后自动提交扫描任务。跨服务器持续控制器尚未验收。
- 固定几何与其他溶剂模型的通用模板流程。修复解析器不等于所有物理模型已经支持。
