# 第一次计算

本章从一个新的独立计算目录（Case）开始，用菜单完成默认的“中性结构优化 + 五点扫描”。
请先[安装程序](INSTALLATION.md)，并准备可用的 VASP/VASPsol 环境。
真实计算要等待集群任务结束，不能把下面各阶段连续执行到底。

已有 Case 请从[当前阶段](index.md#继续已有计算)继续，不要重新初始化。

## 开始前确认方法

这里执行固定 `NELECT` 扫描，不是直接恒电势求解。默认各点都会优化结构；
固定几何、其他溶剂模型或其他 VASPsol 分支，先核对[计算约定](SCIENTIFIC_CONVENTIONS.md)。
SHE 标定必须匹配你的方法，界面起始值不是通用常数。

中性计算默认使用全新密度，扫描点使用中性 CHGCAR 初猜（CHGCAR-only），不读取 WAVECAR。
初始化和准备是不同步骤：**准备中性及扫描点时仍会应用阶段参数**，不能只检查原模板。

## 1. 准备目录

**操作：** 每个体系单独建目录，不放在程序源码目录里。准备以下输入和本机脚本：

```text
my-case/
├── POSCAR
├── INCAR
├── POTCAR
├── KPOINTS
└── vasp.slurm
```

POSCAR 应包含元素名称行，POTCAR 顺序须与之相同。INCAR 已有有效 KSPACING 时可省略 KPOINTS；
两者都在时以 KPOINTS 为准。不要求已有 OUTCAR、WAVECAR 或收敛参考计算。

**完成信号：** 在该目录运行 `vaspsolkit`，选 `10`，基础输入检查通过后进入第 2 步。
这只确认输入可读，不证明计算参数已做收敛测试。

**缺文件时：** 选 `14`，用自己的模板和合法赝势库[补齐输入](inputs.md)，再检查。
已有错误文件不会被自动覆盖，先核对具体报错。

## 2. 打开并初始化

**操作：** 在新 Case 中打开菜单，选 `11`，核对调度器、脚本、SHE 参考值与来源、INCAR 参数后确认：

```bash
cd "/path/to/my-case"
vaspsolkit
```

以下是菜单中的相关选项，按阶段使用，不是一次性输入的命令：

```text
11  初始化 Case 配置
20  准备中性结构优化
21  提交中性任务
22  检查中性任务与收敛
```

**完成信号：** Case 内生成 `vaspsolkit.json` 和 `vaspsolkit.state.json`，菜单允许准备中性任务。
此时还没有提交计算，可以进入第 3 步。

**遇到冲突：** 按提示解决重复或冲突的 INCAR 标签，再初始化。若提示已有配置或状态，
回到原 Case 查看 `03`，不要删除文件强行重来。

如果后续需要组合多个体系，**首次 collect 前**先按[方法记录](reaction.md#先记录方法)
填写各 Case 的 `workflow.method_fingerprint`；相同标识不代替实际方法核对。

## 3. 准备并提交中性任务

**操作：** 选 `20` 准备，再检查生成的 INCAR，确认优化、自旋、溶剂和初猜设置符合自己的方法。
例如默认优化使用 IBRION=2、NSW=200、ISIF=2；完整覆盖项见[阶段配置](SCIENTIFIC_CONVENTIONS.md#incar-profile-行为)。
准备会修改输入并归档旧输出，不是只读检查。

确认后选 `21`。可沿用已有资源配置，也可先选分区，再选自动分配或指定节点。
核对 MPI tasks、节点、时限和脚本，最后输入 `SUBMIT`。

默认 `compute / 1 节点 / 96 tasks / 72:00:00` 不是通用推荐值，可能覆盖脚本中的资源选项。
时限与脚本在提交菜单中沿用配置，需修改时先取消提交，按[服务器配置](CLUSTER_CONFIGURATION.md#选择资源)调整。

**完成信号：** 程序显示 Job ID，任务进入已提交、排队或运行状态。记下 Job ID，进入第 4 步等待，
不要立即再次提交。选 `00` 退出不会取消作业，下次回到同一目录继续。

**未看到 Job ID 或提交断线：** 先核对原作业是否已经创建，按[提交中断处理](recovery.md#提交时断线或出现未决回执)检查，不能据此直接重提。

## 4. 等待并检查中性点

**操作：** 选 `40` 查看已记录任务，任务结束后选 `22` 检查。
需要正常、完整且通过检查的 OUTCAR、CONTCAR、CHGCAR、LOCPOT。

**完成信号：** 中性状态为 `CONVERGED`，才进入第 5 步。
下面是检查输出格式的示例，12345 只是示例 Job ID，不是真实计算记录：

```text
neutral: CONVERGED job=12345
```

| 看到的状态 | 现在怎么做 |
| --- | --- |
| SUBMITTED / QUEUED / RUNNING | 继续等待，稍后再选 `40` / `22` |
| CONVERGED | 通过程序检查，继续准备五点；仍需人工核对结构 |
| NEEDS_REVIEW / FAILED / BLOCKED | 停止推进，查看 `03` 和中性输出，进入[恢复章节](recovery.md) |
| UNKNOWN | 先恢复队列查询并核对原 Job ID，不重提 |

队列中的 COMPLETED 不等于 VASP 已收敛。不要把“检查命令执行成功”当作结果可用。

## 5. 准备和提交五点

**操作：** 中性检查通过后，依次选择：

```text
30  准备带电点目录
31  检查带电点输入
32  选择并提交带电点
```

选 `30` 后，核对各点生成的 INCAR；默认各点从中性 CONTCAR 和 CHGCAR 启动。
默认电子数偏移为 `[-1.0, -0.5, 0.0, 0.5, 1.0]`，目录位于 `charge_sweep/1` 至 `charge_sweep/5`。
其中 `charge_sweep/3` 是独立中性扫描点，根目录中性准备任务不替代它，默认共 **1 + 5 个任务**。

**完成信号：** `31` 报告输入检查通过；`32` 确认提交后，已接受的点各有 Job ID。
进入等待阶段，各点完成后选 `50` 检查，全部为 `CONVERGED` 再进入第 6 步。

**仍有 PREPARED：** 如果设置了 `max_inflight`，未提交的点保留为 PREPARED。
等待在途任务减少后，再选 `32` 提交这些点；程序退出后不会自动补交。
检查失败先修正具体问题，不绕过 `31`；UNKNOWN 或失败状态按[恢复章节](recovery.md)处理。

## 6. 收集并审查五点

**操作：** 五点检查通过后选 `60` 收集，再主动选 `61` 审计。

```{important}
`02` 不会自动执行 `61`。它在收集后可能直接推荐拟合；
请先查看详细审计和原始五点，再决定是否执行 `62`。
```

**完成信号：** `60` 生成 `results/summary.csv`；`61` 生成
`results/quality_report.csv` 与 `results/points_to_rerun.csv`。
这些文件出现或命令显示 `wrote ...`，只说明报告已生成。

打开详细质量表的 `warnings` 列，逐点核对警告，并检查结构、磁态、能量和电势参考。
确认五点均可接受后进入第 7 步；警告为空也不等于科学验收全部通过。
警告含义和检查位置见[读质量报告](results.md#先读质量报告)。

**存在异常：** 保留五个点与原输出，先按[恢复章节](recovery.md)处理，再重新收集和审计；
不要通过删掉中性点凑出曲线。

## 7. 生成曲线并验收

**操作：** 审查完成后选 `62` 生成五点拟合。

**完成信号：** `results/eu/` 中出现 `eu_curve.png`、`eu_curve.csv`、`analysis.json` 和 `report.md`。
先比较原始点与残差，再按[结果验收](results.md#怎么判断结果是否可用)判断是否可用于分析。
拟合顶点不自动等于 PZC，电子能量不自动等于完整 Gibbs 自由能。

**拟合被拒绝：** 检查点数、唯一中性点和各点纳入状态，回到数据检查；不使用诊断豁免替代最终验收。
再次拟合会覆盖 `results/eu/` 中的同名文件；保留旧结果的方法见[输出文件](results.md#输出文件)。
